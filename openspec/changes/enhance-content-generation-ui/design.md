# Design: Enhance Content Generation UI

## Context

目前的使用者介面存在以下問題：
1. **功能混亂**: 管理功能（品質分數、統計圖表）與一般使用者功能混合在同一介面
2. **缺乏個人化**: 使用者無法調整 AI 內容生成的風格、語氣、深度等參數
3. **操作繁瑣**: 需要手動點擊生成按鈕，無法自動載入新內容
4. **意見反饋位置不當**: '意見'按鈕位於文章卡片內，不適合進行整體方向調整

現有架構基於：
- Next.js App Router + TypeScript
- Firestore 作為主要資料儲存
- Ollama 瀏覽器端整合進行 AI 內容生成
- React Hooks 架構（useContentGeneration, useAuth 等）
- Tailwind CSS 進行樣式設計

## Goals / Non-Goals

**Goals:**
- 提供個人化內容生成設定介面（語氣、風格、深度、長度、主題、新鮮度）
- 實現內容方向微調功能，允許使用者即時調整整體文章生成方向
- 實現自動無限滾動，提升內容瀏覽體驗
- 簡化使用者介面，根據登入帳號的角色顯示不同 UI；管理者保留品質分數、統計圖表等管理資訊，普通使用者則隱藏這些資訊，只顯示內容卡、讚/不讚 與設定按鈕。
- 保持現有架構穩定性，最小化破壞性變更

**Non-Goals:**
- 不修改現有的 AI 生成核心邏輯
- 不改變 Firestore 資料結構
- 不重新設計認證系統
- 不修改現有的內容卡片基本功能
- 不添加複雜的後端服務

## Decisions

### 1. UI 架構決策

**決策**: 採用抽屜式（Drawer）設計模式
**理由**: 
- 抽屜式設計不佔用主要內容空間
- 符合現代移動端設計趨勢
- 可以包含豐富的設定選項而不影響閱讀體驗
- 與現有的側邊欄架構相容

**替代方案考慮**:
- 彈出式 Modal: 會遮擋內容，不適合長時間設定
- 頁面路由: 會中斷閱讀流程
- 工具提示: 無法容納複雜的設定選項

### 2. 設定儲存策略

**決策**: 使用 Firestore 儲存使用者偏好設定
**理由**:
- 與現有架構一致
- 支援跨裝置同步
- 可以記錄設定變更歷史
- 與現有的用戶資料結構相容

**資料結構**:
```typescript
interface UserPreferences {
  uid: string
  contentSettings: {
    tone: 'casual' | 'professional' | 'friendly' | 'academic'
    style: 'narrative' | 'analytical' | 'conversational' | 'technical'
    depth: 'brief' | 'moderate' | 'deep' | 'comprehensive'
    length: 'short' | 'medium' | 'long' | 'detailed'
    topic: 'trending' | 'educational' | 'news' | 'opinion' | 'tutorial'
    freshness: 'latest' | 'recent' | 'timeless' | 'classic'
  }
  updatedAt: Timestamp
}
```

### 3. 設定抽屜整合微調功能

**決策**: 在設定抽屜中整合即時微調功能
**理由**:
- 避免功能重複，統一使用者體驗
- 將所有個人化設定集中在一個介面
- 減少 UI 複雜度和維護成本
- 提供一致的操作邏輯

**實現方式**:
- 在設定抽屜中添加即時微調選項
- 微調參數影響後續內容生成
- 不修改已存在的內容
- 提供預覽功能讓使用者確認調整效果

### 4. 無限滾動實現

**決策**: 使用 Intersection Observer API + 200px 預載入距離
**理由**:
- 原生 API 效能優於滾動事件監聽
- 200px 距離提供良好的使用者體驗
- 可以處理大量內容的效能問題
- 與現有的 useInfiniteScroll hook 相容

**優化策略**:
- 虛擬化列表（如果需要）
- 懶載入圖片和媒體內容
- 節流機制避免頻繁觸發

### 5. 組件架構決策

**決策**: 創建獨立的設定和微調組件
**理由**:
- 關注點分離，便於維護
- 可以獨立測試和重用
- 符合 React 組件設計原則
- 支援未來功能擴展

**組件結構**:
```
components/
├── SettingsDrawer.tsx          # 設定抽屜主組件，根據使用者角色顯示不同設定與微調選項
├── ContentDirectionTuner.tsx   # 內容方向微調組件，僅在普通使用者界面中顯示
├── UserPreferenceForm.tsx      # 偏好設定表單，支援管理者與普通使用者的不同預設值
└── InfiniteScrollTrigger.tsx   # 無限滾動觸發器，適用於所有使用者
```

## Risks / Trade-offs

### 風險與緩解策略

**[風險] 設定複雜度過高** → **緩解策略**
- 提供預設值和快速設定選項
- 使用圖示和說明文字降低學習成本
- 支援一鍵重置為預設設定

**[風險] 效能影響** → **緩解策略**
- 設定變更採用防抖動機制
- 內容生成使用佇列管理
- 實施適當的快取策略

**[風險] 使用者體驗不一致** → **緩解策略**
- 統一的設計語言和互動模式
- 詳細的使用指南和提示
- A/B 測試驗證設計決策

**[風險] 向後相容性** → **緩解策略**
- 漸進式功能啟用
- 保留現有功能的降級方案
- 詳細的遷移文檔

### 權衡考量

**功能豐富度 vs 簡潔性**
- 選擇提供核心功能，避免過度設計
- 支援進階使用者的高級選項
- 保持介面的直觀性

**個人化程度 vs 系統複雜度**
- 平衡個人化選項的數量和實作複雜度
- 專注於最有價值的個人化維度
- 避免過度工程化

**即時反饋 vs 系統效能**
- 優先使用者體驗，但確保系統穩定性
- 實施適當的載入狀態和錯誤處理
- 提供手動刷新選項作為備用方案

## Migration Plan

### 階段 1: 基礎設施建設
1. 建立新的組件架構
2. 實作設定儲存機制
3. 創建基本的 UI 框架

### 階段 2: 核心功能實現
1. 實作設定抽屜介面
2. 整合個人化參數到內容生成
3. 實現內容方向微調功能

### 階段 3: 進階功能
1. 實作無限滾動機制
2. 優化使用者介面
3. 添加動畫和過渡效果

### 階段 4: 測試與優化
1. 功能測試和效能調優
2. 使用者體驗測試
3. 錯誤處理和邊界情況處理

### 部署策略
- 使用功能旗標（Feature Flags）控制新功能啟用
- 漸進式推出，監控使用者反饋
- 準備快速回滾機制

## Open Questions

1. **個人化參數的預設值**: 需要確定各項設定的預設值和推薦值
2. **微調功能的影響範圍**: 確認微調是影響後續生成還是包含已生成內容
3. **無限滾動的效能極限**: 需要測試大量內容時的效能表現
4. **設定同步策略**: 確認跨裝置和跨會話的設定同步機制
5. **錯誤處理**: 定義各種失敗情況的使用者體驗和回退機制
