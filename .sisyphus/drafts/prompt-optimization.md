# Draft: Prompt 參數優化研究

## 原始問題
用戶發現當前AI內容生成平台的問題：
1. 生成的文章太短
2. 內容太空泛  
3. 需要使用真實LLM而非mock data
4. 猜測是prompt參數設定不合適

## 核心問題
是否需要另外寫一個程式來調校出最好的prompt參數組合？

## 現有系統分析（已完成）

### 1. prompt-builder.ts 關鍵設定
- **深度等級**:
  - brief: 200-300字（簡短摘要）
  - standard: 400-600字（預設值） ← 可能太短
  - deep: 800-1200字（深度分析）
- **溫度參數**: 
  - 基礎溫度: 0.7 (ollama-client.ts)
  - 在prompt-builder中計算：預設0.8，根據模式調整（creative: 0.9, focused: 0.6）
- **提示詞模式**: 
  - legacy: 舊的提示詞系統
  - modular: 模組化提示詞（有角色、觀點、格式、深度模組）
- **生成格式**: JSON物件格式 {content, keywords, topics, style}

### 2. generate/route.ts 流程
- 檢查cache → 查新聞 → 建構提示詞 → 呼叫LLM
- 預設使用standard深度（400-600字）
- 溫度: 0.8 (系統預設)

### 3. 問題診斷
1. **文章太短原因**：預設使用standard深度（400-600字），可能不夠
2. **內容太空泛原因**：溫度設定、新聞素材質量、提示詞指導不夠具體
3. **真實LLM使用**：目前環境變數 `NEXT_PUBLIC_USE_MOCK_DATA` 控制

## 使用者需求分析
- 文章長度：需要更長、更詳細內容（可能800字以上）
- 內容質量：需要更深入、具體的內容，而非泛泛而談
- LLM使用：確定需要使用真實LLM（Ollama gemma3:12b-cloud）
- 參數調校：需要系統化的參數優化方法

## 潛在解決方案
1. 調整深度等級到deep（800-1200字）
2. 優化溫度參數（可能需要更低溫度以獲得更聚焦內容）
3. 修改提示詞系統以提供更具體指導
4. 確保新聞素材質量足夠高
5. 建立參數調校系統

## 核心決策點
是否需要寫一個完整的參數調校程式？這涉及：
- 多參數組合測試（温度、top_p、max_tokens等）
- A/B測試機制
- 質量評估標準
- 自動化調校流程
